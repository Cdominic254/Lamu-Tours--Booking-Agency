## 4. Functional Requirements

Use IDs like `FR-<AREA>-<NUMBER>` for traceability.

### 4.1 Discovery & Search

- **FR-DISC-01**: As a tourist, I can search experiences by date, category (e.g., boat, tour, stay), and price range.
- **FR-DISC-02**: As a tourist, I can see real-time availability for each experience.
- **FR-DISC-03**: As a tourist, I can view operator ratings and reviews.

<!-- Other Requirements -->

### 4.2 Booking

- **FR-BOOK-01**: As a tourist, I can select date/time, number of participants, and complete a booking.
- **FR-BOOK-02**: As a tourist, I receive a confirmation with experience details, date/time, participants, total price, and operator contact.
- **FR-BOOK-03**: As an operator, I can see all bookings in a calendar/list view.
- **FR-BOOK-04**: As an operator, I can set capacity per time slot and prevent overbooking.


### 4.3 Payments

- **FR-PAY-01**: As a tourist, I can pay via mobile money (e.g., M-Pesa) and/or card.
- **FR-PAY-02**: As an operator, I can see payout status and history.
- **FR-PAY-03**: As an admin, I can configure commission rates and payout rules.



### 4.4 Operator Management

- **FR-OP-01**: As an operator, I can create and edit experiences with title, description, photos, price, terms, and capacity.
- **FR-OP-02**: As an operator, I can save drafts and publish experiences when ready.
- **FR-OP-03**: As an admin, I can verify operators (KYC) and approve/reject experiences before they appear in search.



### 4.5 Notifications

- **FR-NOTIF-01**: As a tourist, I receive booking confirmation and reminders via SMS and/or push notification.
- **FR-NOTIF-02**: As an operator, I receive alerts for new bookings, changes, and cancellations.



### 4.6 Authentication & Authorization

- **FR-AUTH-01**: Users can register and log in as tourist, operator, or admin.
- **FR-AUTH-02**: Access to features is restricted by role (tourist, operator, admin).



## 5. Non-Functional Requirements

Use IDs like `NFR-<AREA>-<NUMBER>`.

### 5.1 Performance

- **NFR-PERF-01**: Search results load in < 2 seconds on 3G connections under normal load.
- **NFR-PERF-02**: Each step in the booking flow completes in < 3 seconds under normal load.

### 5.2 Availability

- **NFR-AVAIL-01**: System availability of 99% during peak tourist hours (e.g., 08:00–22:00 local time).

### 5.3 Security & Privacy

- **NFR-SEC-01**: All traffic is encrypted using HTTPS.
- **NFR-SEC-02**: Personal data and payment information are stored securely; raw card data is never stored.
- **NFR-SEC-03**: Role-based access control is enforced for all API endpoints.

### 5.4 Scalability

- **NFR-SCALE-01**: System supports [X] concurrent users and [Y] bookings per day initially, with a clear path to scale horizontally.

### 5.5 Usability

- **NFR-USE-01**: The app works on low-end Android devices (specify minimum OS version and RAM if known).
- **NFR-USE-02**: Data usage is minimized via image optimization, caching, and lazy loading.
